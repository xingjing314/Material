# 软考AI最小业务推理语义 V0 草案

## 1. 文档目的

本文用于记录软考AI当前已经达成共识的最小业务推理语义。

当前阶段已经完成平台目标与用户基础领域Definition的V1冻结，并开始进入：

> **阶段3：用户问题与现状研究**

阶段2主要定义了：

- 平台最高结果目标；
- 用户参与软考的现实价值诉求；
- 用户所处的组织环境；
- 用户当前的信息化认知尺度；
- 用户当前已经具备的信息化知识结构；
- 用户相对稳定的学习/认知特征；
- 用户当前的资源约束。

这些Definition分别描述自身是什么，但不负责定义它们在具体AI业务判断中的完整关系。

因此，阶段3开始时需要一个最小推理语义，用于回答：

> **AI面对一个具体用户问题时，应在什么业务语义环境中理解该问题，并从什么基本判断路径形成回答策略。**

本文只记录当前已经认可的最小结构，不扩展为完整Reasoning System。

---

# 2. 核心原则

## 2.1 不定义AI真实内部思维过程

本文不规定模型内部必须：

1. 先思考什么；
2. 再思考什么；
3. 采用多少个推理步骤；
4. 使用何种Chain-of-Thought；
5. 使用单Agent还是多Agent。

本文关注的是：

> **AI进行业务判断时，应处于什么业务语义环境，以及最终业务判断应受哪些基本语义约束。**

因此：

```text
Reasoning Semantics
≠
真实内部推理过程
≠
Runtime Workflow
≠
Agent Graph
```

---

## 2.2 Current Question 是当前任务中心

用户当前提出的问题是当前AI任务的直接对象。

例如：

> “数据治理的核心步骤是什么？”

AI最终需要解决的中心任务仍然是这个问题本身。

Platform Goal、User Current State、Exam / Course Required State、Evidence等对象：

> **用于限定、解释、校正和约束AI如何理解和回答Current Question，而不是替代Current Question。**

---

## 2.3 各输入不是线性权重关系

Reasoning Frame中的不同对象承担不同业务语义角色。

它们之间不表示：

```text
Platform Goal = 40%
User Current State = 25%
Exam Requirement = 20%
Evidence = 15%
```

也不表示某个对象天然比Current Question“权重更大”。

当前V0不定义任何固定权重、评分或数值优先级。

---

# 3. Reasoning Frame

## 3.1 定义

**Reasoning Frame** 用于描述：

> AI理解和判断一个Current Question时所处的最小业务语义环境。

当前V0定义为：

```text
Reasoning Frame

Platform Goal
+
User Current State
+
Exam / Course Required State
+
Evidence
```

---

## 3.2 Platform Goal

当前平台最高结果目标：

> **通过考试**

Platform Goal用于提供整个软考AI业务判断的产品方向和不可突破的上位边界。

它不表示：

- 所有回答都必须反复强调考试；
- Platform Goal替代Current Question；
- Platform Goal可以覆盖用户当前问题的具体语义。

它表示：

> AI对当前问题进行教学、扩展、解释和策略选择时，不得使产品行为偏离“帮助用户通过并应对真实考试”的最高结果目标。

---

## 3.3 User Current State

User Current State用于描述：

> 当前这个用户是什么状态。

当前主要由阶段2已经形成的用户基础Definition提供语义基础：

```text
participation_goal
organization_environment
informatization_cognition_maturity
informatization_knowledge_structure
learning_cognition_characteristics
resource_constraints
```

其中：

### participation_goal

描述用户当前参加软考的现实动机和价值诉求。

它的内容可能指向未来收益，例如：

- 职位晋升；
- 薪资提升；
- 落户；
- 政府补贴；
- 入编；
- 单位投标；
- 退休待遇提升；
- 就业竞争力提升；
- 信息化能力提升。

但在当前推理语义中：

> participation_goal被视为User Current State中的当前参与动机 / 现实价值诉求。

它不属于Platform Goal，也不能覆盖Platform Goal。

participation_goal未来可能影响个性化教学策略，但V0不定义这种影响的具体Mapping。

---

## 3.4 Exam / Course Required State

Exam / Course Required State用于描述：

> 针对当前考试、课程、知识点或题型，用户为了达到考试目标需要具备什么。

当前该领域尚未正式建模。

因此V0只保留这一语义位置，不定义：

- 正式Course Requirement；
- 正式Exam Requirement；
- 完整知识要求；
- 能力要求；
- 题型能力要求；
- 论文能力要求；
- Formal Gap计算规则。

该部分将在后续考试与教学领域建模中继续明确。

---

## 3.5 Evidence

Evidence用于表示：

> AI进行当前业务判断时可以依据的事实、材料、观察结果或可靠信息来源。

当前V0只确认Evidence是Reasoning Frame的一部分。

V0暂不定义：

- Evidence类型；
- Evidence等级；
- Evidence可信度；
- Evidence优先级；
- RAG证据结构；
- 用户行为证据；
- 真题证据；
- 教材证据；
- 外部政策证据；
- Evidence冲突处理规则。

---

# 4. Reasoning Path

## 4.1 定义

**Reasoning Path** 用于描述：

> AI在Reasoning Frame约束下，从Current Question形成与当前任务相关的业务判断，并最终形成回答策略和答案的最小语义路径。

当前V0定义为：

```text
Current Question
+
Reasoning Frame
        ↓
Relevant Gap / Barrier
        ↓
Strategy
        ↓
Answer
```

---

## 4.2 Current Question

Current Question始终是当前任务中心。

AI首先需要理解：

> 用户现在具体在问什么。

Reasoning Frame不是Current Question的前置外挂，也不是一组固定Prompt背景。

它是：

> **贯穿AI对Current Question理解、判断、策略选择和回答过程的业务语义环境。**

---

## 4.3 Relevant Gap / Barrier

Relevant Gap / Barrier表示：

> 与Current Question和当前考试目标直接相关的差距、障碍或限制。

当前V0使用：

> `Relevant Gap / Barrier`

而不是直接定义完整Formal Gap。

原因是当前尚未正式完成：

```text
Exam / Course Required State
```

因此还不能严格定义：

```text
Formal Gap
=
Required State
-
Current State
```

阶段3可以识别和研究：

- 已观察到的学习障碍；
- 已观察到的理解困难；
- 已观察到的知识断层；
- 已观察到的考试迁移困难；
- 已观察到的时间和资源限制；
- 其他真实用户问题。

但这些Observed Barrier / Pain不等同于已经完成正式Gap计算。

---

## 4.4 Strategy

Strategy表示：

> AI基于Current Question、Reasoning Frame以及Relevant Gap / Barrier，对“如何回应当前问题”形成的业务策略。

Strategy未来可能影响：

- 回答深度；
- 解释起点；
- 是否补充必要背景；
- 是否使用类比；
- 是否调用RAG；
- 是否需要教材外必要补充；
- 是否控制技术深挖；
- 是否需要练习或验证；
- 是否需要调整表达颗粒度。

当前V0不定义具体Strategy类型、规则、Mapping或Runtime实现。

---

## 4.5 Answer

Answer表示：

> AI在当前业务语义环境和策略约束下，对Current Question形成的最终用户可见回答。

V0不要求Answer暴露模型真实Chain-of-Thought。

未来如果需要验证AI是否遵守Reasoning Semantics，应优先验证：

- 使用了哪些业务事实；
- 使用了哪些Evidence；
- 应用了哪些约束；
- 形成了什么业务判断；
- 最终回答是否符合产品目标和业务边界。

而不是要求模型公开完整内部思维过程。

---

# 5. Reasoning Frame 与 Reasoning Path 的关系

二者职责不同。

```text
Reasoning Frame
回答：
“AI应该在什么业务语义环境里理解当前问题？”

Reasoning Path
回答：
“AI在这个环境下，如何从当前问题形成相关业务判断，并走向回答？”
```

因此：

```text
Reasoning Frame
≠
Reasoning Path
```

同时：

```text
Reasoning Path
≠
程序执行Chain
≠
LangGraph Graph
≠
Agent Workflow
```

Runtime未来可以使用不同技术执行同一套业务推理语义。

例如：

- 单次LLM；
- RAG + LLM；
- 规则 + LLM；
- LangGraph；
- 单Agent；
- Multi-Agent；
- 其他未来Runtime。

具体实现变化不应自动改变本文定义的业务推理语义。

---

# 6. 当前V0的最小约束

当前至少确认以下约束：

1. Reasoning Frame中的各输入不是线性权重关系。
2. Current Question始终是当前任务中心。
3. Platform Goal用于提供产品最高方向和边界，不替代Current Question。
4. participation_goal属于User Current State中的当前参与动机 / 现实价值诉求，不覆盖Platform Goal。
5. User Current State中的不同维度不能被无依据地相互推导。
6. 组织环境不能直接推出用户个人学习能力或知识水平。
7. 资源投入时间不能直接推出用户知识掌握程度。
8. 较高的信息化认知成熟度不能直接推出用户已经掌握全部相关专业知识。
9. “信息化能力提升”参与目标不能使平台偏离考试目标并转向深层专项技术培训。
10. Current Question、Reasoning Frame、Relevant Gap / Barrier、Strategy和Answer之间描述的是业务推理语义，不等于模型内部真实思维步骤或固定Runtime顺序。

---

# 7. 与阶段3的关系

本文当前主要用于：

> **为阶段3“用户问题与现状研究”提供最小业务推理锚点。**

阶段3研究真实用户问题时，不应仅收集孤立的“用户抱怨”。

应尽量保留以下语义背景：

```text
Current Question / Observed Problem
+
User Current State
+
Platform Goal
+
当前可获得Evidence
```

并观察：

> 哪些Barrier / Pain在真实用户中反复出现。

阶段3的真实用户研究可以反向验证：

- Reasoning Frame是否缺少重要语义对象；
- Relevant Gap / Barrier的理解是否合理；
- Evidence是否需要进一步分类；
- participation_goal是否确实影响教学策略；
- 哪些关系未来值得进入正式Mapping。

---

# 8. 当前明确不做的事情

V0阶段不继续设计以下内容：

- Reasoning Engine；
- Reasoning OS；
- 完整Reasoning Contract；
- Chain节点；
- Graph边；
- Multi-Agent继承机制；
- Agent权限；
- Runtime Enforcement；
- Verifier；
- Evidence Schema；
- Gap Engine；
- Strategy Engine；
- Prompt Builder；
- JSON Schema；
- Reasoning Mapping正式结构。

这些内容只有在后续业务和工程需求实际出现时再逐步设计。

---

# 9. 当前状态

当前状态：

> **Draft / V0 / 非正式基线**

当前用途：

> 记录已经达成共识的最小业务推理语义，并作为阶段3用户研究的临时统一理解。

当前原则：

> **先用真实用户问题验证，再决定是否扩展。**

如果阶段3或后续考试领域建模发现新的事实，应优先修正业务语义，而不是为了维持V0结构而强行解释新证据。
