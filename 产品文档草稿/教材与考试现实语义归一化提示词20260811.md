# 四、语义归一化基本原则

## 1. 不限制候选主题数量

不要预先设定：

- 10个；
- 15个；
- 20个；
- 或任何其他目标数量。

候选主题数量必须由输入材料中实际存在的独立语义自然决定。

禁止：

> 为了让结果更简洁，而把多个不同语义强行压缩成少量“大主题”。

同样禁止：

> 为了显得分析更细，而把本质相同的观点人为拆成多个主题。

# 五、主题合并规则

## 1. 只有表达“同一个现实”时才合并

例如：

A：

“第四版教材由多套知识体系拼合而成。”

B：

“教材的信息化、项目管理、绩效域、组织治理等内容不是天然统一体系。”

如果你判断二者表达的是同一个核心现实，可以归入同一候选主题。

## 2. “相关”不等于“同义”

例如：

A：

“教材由多个知识体系拼合。”

B：

“十大知识领域与绩效域存在管理范式差异。”

两者高度相关，但可能分别描述：

- 教材知识组织问题；
- 项目管理范式差异。

如果核心语义不同，不得因为二者属于同一个“大问题”就直接合并。

## 3. 无法确定是否应合并时

遵循：

> 宁可暂时保留两个候选主题，也不要错误合并。

并将二者标记为：

`possibly_related`

说明为什么它们可能有关联，但暂时不建议合并。

## 4. 错误拆分与错误合并的处理原则

本轮优先保证：

> Semantic Recall

也就是尽量不丢失原始语义。

因为：

错误拆得较细  
→ 后续仍可以合并

错误合并  
→ 后续可能无法恢复原始业务含义

因此本轮采取：

> 保守合并原则。

# 七、本轮不进行来源权重判断

本轮只比较：

不要因为：

- 某AI进行了联网搜索；
- 某AI表达更专业；
- 某AI提到了更多数字；

就在本轮提高或降低其观点权重。

特别注意：

> “语义归一阶段，观点可以平等比较；  
> 证据等级和可信度将在后续独立阶段处理。”

因此本轮不要输出：

- 谁最可信；
- 哪个AI最好；
- 哪个观点一定正确；
- 多数模型支持所以一定成立。

# 八、不得使用外部知识重新分析

不要补齐它。

# 九、需要识别的五种语义关系

对5份材料进行完整分析后，应识别以下类型。

## A. normalized_same

多个来源实际上表达同一个核心现实。

应归一化为一个候选主题，并保留全部来源。

## B. related_but_distinct

多个观点明显相关，但核心语义不同。

不得合并。

需要说明它们为什么相关、为什么仍应独立。

## C. source_unique

只在一个来源中明确出现的独有观点。

独有不代表错误。

必须完整保留，不得因为缺乏其他来源支持而删除。

## D. apparent_conflict

不同来源对同一对象存在明显不同甚至互相冲突的判断。

例如可能包括：

- 考试趋势不同；
- 权重判断不同；
- 对教材作用的判断不同；
- 对某类考试要求的描述不同。

本轮不要裁决谁正确。

只识别冲突并保留双方观点。

## E. uncertain_relation

无法可靠确定是同义、相关还是不同的问题。

不得强行判断。

明确标记：

`uncertain_relation`

交给后续人工/AI评审。

# 十、归一化主题要求

每个候选主题应尽量保持：

> 单一、清楚、可区分的业务语义。

不要使用过度宽泛的标题，例如：

- “教材问题”
- “考试问题”
- “知识问题”
- “项目管理问题”

应形成能够独立理解的主题名称。

例如：

“教材由多套知识体系拼合且跨体系整合不足”

比：

“教材体系问题”

更适合作为候选主题。

# 十一、每个候选主题的输出结构

每个候选主题至少包含：

### Theme ID

使用稳定的本次分析标识：

```text
T001
T002
T003
...
```

该ID仅用于本次语义归一化结果，不代表正式Domain ID。

### 主题名称

用一句较短文字表达该主题的核心现实。

### 归一化描述

说明：

> 不同来源在这个主题上实际共同或分别表达了什么。

要求尽量保持原始材料语义。

不要加入新的结论。

### 来源

例如：

```text
my
grok
qwen
```

### 各来源对应观点

分别简要记录各来源在这个主题上表达的内容。

不要因为已经归一化，就只保留一个统一版本。

### 关系类型

使用：

- `normalized_same`
- `source_unique`

对于属于独立候选主题但与其他主题存在明显关系的，可另外记录：

- `related_but_distinct`
- `possibly_related`

### 语义边界

说明：

> 这个主题描述什么，以及它暂时不包括什么。

这一项用于防止后续再次错误合并。

# 十二、独有观点必须单独整理

# 十三、冲突观点必须单独整理

请输出：

## Apparent Conflicts

对存在明显冲突的观点记录：

- 冲突ID；
- 涉及主题；
- 来源A及其观点；
- 来源B及其观点；
- 冲突具体在哪里；
- 是否可能只是统计口径、时间范围或表达层级不同。

不得判断哪一方正确。

# 十四、相关但不应合并的主题

请输出：

```text

```

并说明：

- 为什么相关；
- 为什么当前不建议合并。

这一部分非常重要。

目标是防止后续为了压缩主题数量而错误聚类。
